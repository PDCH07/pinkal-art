# Build contract for pinkal.art (supplements brief.md; where the two differ, THIS FILE WINS)

Repo: C:\git\personal\pinkal_website  (Windows; Python 3.13; Pillow 12 with AVIF; Jinja2 3.1; fontTools 4.65; segno 1.6; Playwright for Python with Chromium; Node 24 only for QA tools, never shipped)

## 1. Deployment model (deviation from brief section 13)
GitHub Pages keeps deploying from branch `main`, folder `/` (root). The build writes its OUTPUT INTO THE REPO ROOT and the output is committed. No GitHub Actions, no `dist/`. Reason: switching Pages to an Actions deploy needs a settings change in the GitHub UI that cannot be made from this machine.

Hand-edited sources:
- `data/works.json`, `data/rooms.json`, `data/site.json`, `data/strings.en.json`, `data/strings.de.json`
- `src/templates/*.html` (Jinja2), `src/css/*.css`, `src/js/*.js`
- `tools/*.py`, `tools/requirements.txt`, `README.md`
- `sources/NN.jpg` (the 42 originals; already moved there from `images/fulls/`; committed, never linked from any page)

Generated by `python tools/build.py` and committed (never hand-edited):
- `index.html`, `404.html`, `works/`, `rooms/`, `de/`, `enquire/`, `show/`, `impressum/`, `datenschutz/`
- `assets/` (hashed `styles.<hash8>.css`, `site.<hash8>.js`, `room.<hash8>.js`, `show.<hash8>.js`), `fonts/` (woff2 + fonts.css from tools/fonts.py; already present)
- `images/r/` (variants, from tools/images.py), `images/qr/` (SVG), `og/` (JPEG cards), `data/images.json`
- `sitemap.xml`, `robots.txt`, `manifest.webmanifest`, `.nojekyll`, `build/CHECKLIST.md`, `build/REVIEW.csv`, `build/manifest.json`
- build.py records every generated path in `build/manifest.json` and deletes paths from the previous manifest that it did not regenerate (never anything else).
- Legacy files to delete in the final integration step (not by parallel agents): `styles.css`, `script.js`, `images/thumbs/`; the old root `index.html` is overwritten.

All URLs in generated HTML are ROOT-ABSOLUTE (`/images/r/13-800.avif`, `/works/13/`, `/assets/...`). Local preview: `python -m http.server` from the repo root.

## 2. File ownership during the parallel build (an agent edits ONLY its own files)
- DATA agent: `data/works.json`, `data/rooms.json`, `data/site.json`, `data/strings.en.json`, `data/strings.de.json`
- PIPELINE agent: `tools/images.py` (rewrite), `tools/fonts.py` (exists, works; may improve), `tools/og.py`, `tools/qr.py`, `tools/requirements.txt`, regenerates `images/r/` and `data/images.json`
- TEMPLATES agent: `tools/build.py`, `tools/check.py`, `src/templates/**`, `src/css/**`, `README.md`
- JS agent: `src/js/site.js`, `src/js/room.js`, `src/js/show.js`

## 3. `data/images.json` (written by images.py, read by build.py). Keys are work ids.
```
"13": {
  "src": "sources/13.jpg", "w": 3051, "h": 2458, "ar": 1.2413, "long_edge": 3051,
  "maxw": 2034,                      // floor(w / 1.5), CSS px cap for the hang
  "eligible_lead": true,             // long_edge >= 2400
  "variants": [ {"w": 200, "h": 161, "avif": "/images/r/13-200.avif", "jpg": "/images/r/13-200.jpg", "bytes_avif": 4321, "bytes_jpg": 6543}, ... ],
  "lqip": "data:image/jpeg;base64,...",   // 24 px long edge, <= 650 bytes
  "wall": "#f3e2de", "deep": "#230c09",   // OKLCH-clamped per brief section 8 (wall L .925 C<=.02; deep L .19 C<=.04), contrast-verified
  "palette": [ {"hex": "#..", "share": 0.31}, ... ]
}
```
Variant widths: 200, 400, 800, 1200, 1600, 2000 (each only if <= source width), plus the source width itself when it lies between two steps or below 200; 2400 only for works with `zoom: true` in works.json (if there is no such work yet, no 2400 variants exist). Portrait sources: widths are image widths; also cap height at 2400. AVIF quality 58 speed 6; progressive JPEG quality 78 optimize; EXIF orientation applied; metadata stripped; never upscale. images.py must clear stale files in `images/r/` that are not in the new variant set (the folder currently holds files from an earlier run with other widths). Works are discovered from `data/works.json` (ids), sources read from `sources/<id>.jpg`. Until works.json exists, fall back to every `sources/*.jpg`.

## 4. Data files

Required: id, kind, room, order, subject{en,de}, alt{en,de}, title_status, zoom, desc_approved. `data/rooms.json`: `[{slug, slug_de, name{en,de}, text{en,de}, lead, order}]` for rain, india, landscapes, animals, music-and-colour (texts <= 45 words, subject first, no counts).
`data/site.json`: exactly per brief section 13, with `legal.*` = "TODO" where unknown, plus `"show_proposed_titles": false`.
`data/strings.en.json` / `strings.de.json`: flat dotted keys, identical key sets, `{name}` placeholders. Keys listed in brief section 12 plus whatever templates need: `meta.*` (titles/descriptions per page type), `show.*`, `legal.*`, `works.heading`, `rooms.*`, `pager.prev/next`, `related.heading`, `hint.de`, `form.*` including errors and `form.subject_prefix`, `thanks.*`, `error404.*`, `a11y.*` for icon labels, `room.*` for the dialog (counter, close, prev, next, zoom, zoom_out, play, pause, ask, share, share_copied, open_page, fullscreen, painting). ## 6. DOM hooks (TEMPLATES agent renders them, JS agent relies on them)
- Clickable painting anywhere: `<a class="plate__link" href="/works/13/" data-work="13" aria-label="No. 13 · {subject}">` wrapping `<figure class="plate [plate--round|plate--band|plate--capped]" style="--ar:1.2413;--maxw:2034px;--art-wall:#...;" data-work="13">` > `<span class="plate__img" style="background-image:url(lqip)">` > `<picture><source type="image/avif" srcset sizes><img class="plate__pic" src srcset sizes width height alt loading decoding></picture>` </span> `<figcaption class="plate__caption">…</figcaption>` </figure></a>. JS opens the dialog on click (no modifier keys) and `pushState`s the href; without JS the link navigates. When an image has decoded, JS adds `is-loaded` to its `.plate__img` (CSS fades the picture in and removes the blur); CSS must also show images without JS (`html:not(.js)` or `@media (scripting: none)`), and build.py adds `class="js"` to `<html>` via an inline one-liner.
- The dialog partial is rendered ONCE per page that has plates: `<dialog class="room" id="room" aria-labelledby="room-caption-title">` containing `.room__bar-top` (`.room__counter[aria-live=polite]`, `a.room__lang`, `button.room__close`), `button.room__prev`, `button.room__next`, `.room__stage` > `figure.room__figure[tabindex=-1]` > `.room__img-wrap` > `img.room__img`, `.room__bar-bottom` > `.room__caption` (`#room-caption-no`, `#room-caption-title`) + `.room__actions` (`a.room__ask`, `button.room__share`, `button.room__zoom`, `button.room__play`, `button.room__fullscreen`, `a.room__open`), and `.room__progress`. Labels from `#room-data.strings`. Buttons that do not apply get `hidden` from JS.
- Artwork page: the stage is `<a class="plate__link plate__link--stage" href="#room" data-work="13" data-open-room>`; the label's "View" button is `button.label__view[data-open-room]`; the phone bar is `.inquiry-bar` with `a.inquiry-bar__ask` and `button.inquiry-bar__view[data-open-room]`.
- Chips (works and room pages): `nav.chips[aria-label]` > `a.chips__chip[data-room="all|rain|…"][href]`; rows: `div.hang__row[data-room="rain"]` with `style="--row-h:320px"` and optional `data-band`; each room's heading is `h2.room-label[data-room]`. JS filter: show only rows and labels whose `data-room` matches (or all), set `aria-current="page"` on the active chip, `pushState` the chip href; on load derive the active room from the chip whose href equals `location.pathname`. Room pages render only their own rows; the works page renders all rooms' rows in hang order.
- Rail (home): `section.rail` > `button.rail__prev`, `ul.rail__track` (scroll-snap) > `li.rail__item` > plate link, `button.rail__next`.
- Sheet (home): `section.sheet` > `.sheet__wall` > `a.sheet__tile[data-work][aria-label]` > img; `p.sheet__caption[aria-live=polite]` (JS writes the hovered or focused tile's aria-label into it).
- Form: `form.form[data-enhance][action="https://formspree.io/f/xrbqdlkk"][method=post]` with `input[name=_gotcha].form__honeypot`, `input[type=hidden][name=_subject]`, `input[type=hidden][name=work_url]`, `input[type=hidden][name=_next]` (thanks page URL), `select[name=work]#work`, `input[name=name]`, `input[name=email]`, `textarea[name=message]`, `button[type=submit].btn.btn--primary`, `p.form__status[role=status]`; per-field empty `.form__error[id]` elements referenced by `aria-describedby`. JS: on `?work=13` select the work and set `_subject` = `{form.subject_prefix} No. 13 — {subject}` and `work_url`; on submit `fetch` with `Accept: application/json`, states per brief 4.7; without JS the normal POST + `_next` redirect works.
- Share: `button[data-share][data-url][data-title]` → `navigator.share`, else clipboard + toast (`div.toast[role=status]` appended to body).
- Lang hint: `p.lang-hint[hidden]` containing the link; site.js removes `hidden` when `document.documentElement.lang === "en"` and `navigator.language` starts with `de`.
- Show page: `main.show[data-interval=8000]` with `.show__stage > img.show__img`, `.show__caption` (`.show__no`, `.show__subject`, `img.show__qr`), `button.show__pause`, `button.show__fullscreen`, `.show__progress`; data from `#room-data`. The page also contains the printable list `.show__sheet` (plates with QR codes) which JS hides while the slideshow runs.
- Reduced motion: all durations come from tokens that are 0 ms under `prefers-reduced-motion`; JS checks `matchMedia("(prefers-reduced-motion: reduce)")` for autoplay and crossfades.
- View transitions: `@view-transition { navigation: auto; }` in CSS; the artwork page stage img carries `style="view-transition-name: work-NN"`; on list pages JS sets the same name on a plate's img on hover/focus and removes it on leave, so a plain navigation (JS bypassed by modifier keys, or the dialog's "Open page" link) morphs the thumbnail into the stage.
- Speculation rules on artwork pages: `<script type="speculationrules">{"prerender":[{"urls":["/works/12/","/works/14/"],"eagerness":"moderate"}]}</script>` (prev and next in hang order).

## 7. Simplifications decided (do not re-open)
- Wordmark: the text "Pinkal" set in Fraunces italic 500 at 28 px (24 px on phones), accessible name per language; no traced SVG signature.
- Studio section: photo 99 + paragraph from confirmed fields + hidden slots; detail crops only if `data/crops.json` exists (it does not at launch).
- Not built: `/now/`, `/commission/`, weekly rehang, fontTools instancing, Nu validator (html-validate is used instead), NVDA/VoiceOver sessions, real Formspree submission.
- Fonts: `fonts/` already contains the pinned-axis woff2 files (Fraunces SOFT 30 WONK 0, opsz 9–144, wght 300–700, roman and italic; Instrument Sans wdth 100, wght 400–700) and `fonts/fonts.css`. build.py inlines the `@font-face` rules into the page head with paths rewritten to `/fonts/...`, and preloads only `Fraunces-300-700-normal-latin.woff2` and `InstrumentSans-400-700-normal-latin.woff2`.
- OG cards: `tools/og.py` renders `og/NN.jpg`, `og/home.jpg`, `og/room-<slug>.jpg` (1200 × 630, JPEG q80, <= 150 KB) with Playwright from an inline HTML template that uses the self-hosted fonts; skipped with a warning if Playwright is missing. build.py calls it after HTML rendering.
- QR: `tools/qr.py` writes `images/qr/NN.svg` with segno for eligible leads (error level M, 4-module quiet zone, dark `#141210`, light transparent).
- 404.html: one bilingual file, root-absolute assets.
- Titles: hidden unless `title_status == "confirmed"` or `site.show_proposed_titles` is true.
- Counts in copy come from data through template variables only.
